## Authorization and response codes

- `GET /api/steam-catalog/games` and `GET /api/steam-catalog/taxonomy`
  are public and unchanged.
- `POST /api/steam-catalog/taxonomy`,
  `POST /api/steam-catalog/import`, and
  `PUT /api/steam-catalog/games/:id/classification`
  use the shared `requireSteamCatalogAdmin` middleware **before**
  validation, external fetch or any database operation.
- The API checks `x-steam-catalog-admin-token` against the server-side
  `STEAM_CATALOG_ADMIN_TOKEN`.
- Missing/under-32-character server key: HTTP **503**,
  `STEAM_CATALOG_ADMIN_NOT_CONFIGURED` (fail closed).
- Missing/incorrect client key with valid server config: HTTP **403**,
  `STEAM_CATALOG_ADMIN_REQUIRED`.
- Correct client key: continue to existing handler and original status code.
- Tournament organizer, support and viewer tokens are **not**
  catalog administrator credentials; global catalog rights are separate.
- Credentials are compared as SHA-256 digests via `timingSafeEqual`.
  No credentials or hashes are included in API responses.

## Editor compatibility

The release editor now includes an optional password input on import and
classification screens. It transmits the admin key only on the three
mutation methods, stores it in component memory only and loses it when
the page reloads. This is intentionally more conservative than the
reference editor's per-tab sessionStorage behavior. Public GET requests
never include the key.

## Activation is separately gated

No production secret is installed by this change. An authorized
operator must issue a unique, random, high-entropy server-only key
(at least 32 random bytes), put it into approved server secret storage,
and deliver it to an authorized catalog editor using an approved
private channel. Do not commit, paste into PRs/issues, log, or expose via
public frontend build variables. The catalog remains read-only until
explicit activation. HTTPS is required for credential transport.

The token is a shared administrative capability. It is not individually
revocable and has no built-in audit identity or automatic expiry.
Follow-up RBAC, activity logging, rate limits, rotation and incident
handling need a separately approved scope.

drops/creates only `tm_test_t030_auth` in the test database, applies
the existing release catalog migration 0029, sends requests to the
actual Express router using Supertest, and mocks outbound Steam requests.
It checks public GET, all three real POST/PUT routes, role denials,
503 unconfigured behavior, no DB changes after denial, and authorized
writes to the fixture tables. It does **not** contact a production API,
database, or Steam service.

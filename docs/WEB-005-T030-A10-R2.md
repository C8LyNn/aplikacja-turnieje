## Source-level security verification

The API is mounted in `src/app.ts` via `app.use("/api", router)` and `src/routes/index.ts` via `router.use(steamGameCatalogRouter)`. There is **no generic global catalog authorization middleware** in release. PR #34 inserts `requireSteamCatalogAdmin` before request validation/DB access on:

1. `POST /api/steam-catalog/taxonomy`
2. `POST /api/steam-catalog/import`
3. `PUT /api/steam-catalog/games/:id/classification`

`GET /api/steam-catalog/games` and `GET /api/steam-catalog/taxonomy` retain public access. Tournament-scoped viewer/support/organizer bearer tokens do not grant any catalog-admin privilege. The global key is compared via SHA-256 and `timingSafeEqual` and is not returned to the client. Source-level assertions in R1 passed 13/13; R2 source inspection confirms unchanged guards.

Reference branch contains **additional catalog growth/import-job write routes not present in release**. Do not blindly cherry-pick its entire router/migrations in T030; if future release gains new writes, repeat an endpoint census and guard every such mutation.

## Frontend compatibility and credential-handling assessment

- Public GET requests remain unmodified; no token is attached to reads.
- Import, taxonomy creation and classification saves attach `x-steam-catalog-admin-token` only if entered by the editor.
- The release UI's `adminToken` is React component state (no `sessionStorage` or `localStorage` persistence). This reduces persistence but the token disappears on reload and may need re-entry after route remount; **manual UX check required**.
- Privileged key is still present in browser memory and HTTP request headers: XSS, malicious extensions, network interception without HTTPS, leaked screenshots and inadvertent sharing remain risks. A shared token lacks per-editor revocation, expiration and attribution. Prefer a future authenticated staff role with server-side sessions if the project requires real multi-editor administration.
- No production credential configured. Missing key intentionally blocks editing. Provisioning and authorized distribution must occur only after separate owner approval and staging checks.

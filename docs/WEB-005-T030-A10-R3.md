## Authorization topology and contract

`src/app.ts` mounts `src/routes/index.ts` under `/api`; the index uses the Steam Catalog router. Its **only two** POST endpoints and **only one** PUT endpoint are:

- `POST /api/steam-catalog/taxonomy` — `requireSteamCatalogAdmin` first.
- `POST /api/steam-catalog/import` — `requireSteamCatalogAdmin` before Steam fetch.
- `PUT /api/steam-catalog/games/:id/classification` — `requireSteamCatalogAdmin` before DB queries and transaction.

Public `GET /api/steam-catalog/games` and `GET /api/steam-catalog/taxonomy` are unchanged.

## Frontend security findings

- Exactly 3 mutation calls attach the credential header. Public reads use the original `api()` without the header.
- Credential remains in volatile React state, in `<input type="password" autoComplete="off">`; no sessionStorage/localStorage write/read for this secret. Route remount or reload can clear it. Its re-entry behavior needs manual browser QA.
- Password inputs and nonpersistence do not defeat XSS: same-origin injected scripts or malicious extensions can access in-memory/DOM credentials or intercept requests. Browser autofill settings are not enforceable secrets storage controls.
- The token is still a shared long-lived capability with no individual identity, revocation, expiration or audit. HTTPS and approved operator provisioning are mandatory; production key is **not** configured.

## 2. TS-B R23 atomic transaction proposal — exact ordered contract

**Apply only for:** target match in the *last, terminal Swiss stage*, stage completed, tournament completed, \`tournament.activeStageId===null\`, no later stage started/routed, latest relevant match's final-round result being undone. No terminal-stage REVERT may leave a pending match while both stage and tournament remain completed. Nonterminal Swiss may continue existing bounded branch, if no downstream or approved routing; old stage-independent result guards remain.

1. **Begin ONE transaction** (reusing the transaction parameter already accepted by \`revertMatch\`; never nest another transaction under an held tournament lock). Pre-read immutable match identity only for lock targeting. \`SELECT tournament FOR UPDATE\`; revalidate current organizer/support mutation actor and tenant.
2. Lock **all stages of this tournament in ascending position/id**, including target terminal stage; verify exactly one terminal Swiss stage and correct \`status=completed\`, \`winnerId\` and \`activeStageId=null\`. Refuse mismatch/inconsistent champion, cancelled match, already-open stage/tournament, later running stages, approved qualification or materialized stage routing. Completed single/multi-stage configuration must be consistent; do not skip contradictory data.
3. Lock the **entire target-stage match set in stable (round,matchNumber,id) order before changing standings** (also satisfies controlled \`expectedStageVersionVector\` when supplied), then target match if not already locked. For last-round correction, no later Swiss pairings/currentRound beyond target round; earlier rounds with dependent pairings are still blocked rather than inventing automatic replay of Swiss pairing.
4. Lock only **terminal stage's participant memberships in stable playerId/id order** and the corresponding stage-entrant \`players\` rows in id order. Verify stage participantCount, tenant identity, original qualification/provenance and winner membership. **No global all-player activation**. Prior SE losers outside terminal Swiss \`stage_participants\` stay \`eliminated\` even if tournament winner/global statuses are being cleared. Prior stage finalRank/qualifications remain immutable.
5. Lock the match's latest \`result_history\` row, active \`match_result_submitted\` log (exactly one valid un-undone completion with correct matchId/payload) and the **most recent uncompensated** terminal-stage \`stage_completed\` audit row. Use deterministic \`id\` tie-break; no latest-50 action-log search. If multiple incomplete/ambiguous completion/audit chains, reject and roll back; never guess by timestamps or silently skip damaged history. Ensure \`expectedMatchRevision\`, \`expectedCompletionActionId\`, correction operation receipt/stage vector are verified under this same transaction **when provided by authorized internal callers**.
6. Calculate PRE-MUTATION expected winner state using Swiss whole-stage final standing, not corrected match's winner. Validate \`stage.winnerId === tournament.winnerId === standings champion\` (or an explicit lawful no-winner mode supported by the existing stage contract) and that only entrants have current terminal-stage \`winner/eliminated\` status. Fail closed on contradictory final state. **No new Swiss pairing generator call;** S3/S4 affect future schedule creation, not this reversal.
7. Within the **same transaction**, reset only selected completed match to pending with result/score/reason/winner/completedAt cleared, letting DB match revision mechanism advance under existing controlled rules. **Never delete or rewrite \`result_history\`**; original immutable completion remains traceable and an optional fault hook may deliberately abort the whole transaction.
8. Reopen the terminal \`tournament_stages\` row: \`status=active, completedAt=null, winnerId=null, version=oldVersion+1\`, guarded by previous stage id/version/completed status. Clear terminal-stage-only \`finalRank,qualificationRank,groupRank,nextStageSeed,qualifiedAt\` and restore \`stage_participants.status=active\` for exactly that stage's authentic active entrants; preserve stageSeed, group/qualificationSource/sourceStageParticipantId and unrelated stages. No resurrection across a prior SE eliminated roster or fabricated qualifier.
9. Reopen \`tournaments\`: \`status=active, winnerId=null, activeStageId=terminalSwissStage.id\` using a stale-protected WHERE; update global \`players.status\` **only for true terminal Swiss entrant IDs** as justified by provenance. The prior champion loses \`winner\`, valid stage entrants become \`active\`, all non-entrant prior eliminations remain. Verify one-active-stage unique DB constraint and row counts; unexpected status/row count => typed conflict + full rollback.
10. Compensate **without deleting** the old \`stage_completed\` audit: append a distinct fail-closed \`stage_reopened_for_correction\` audit event bound to tournament/stage/match, linking the original stage-completion action ID and reason/revert action ID by an explicitly reviewed deterministic schema/metadata convention. **Current action_log has no structured compensation-link column and \`undoPayload=null\` for stage_completed; a naive non-null undoPayload would accidentally make the compensation eligible for global Undo.** Favor \`undoPayload=null\` for audit-only compensation. If machine-readable linkage requires new DB column/table, A20 + separate GO must approve; do not overload arbitrary JSON or mutate the original immutable event to masquerade as an Undo. Old match completion gets existing \`isUndone=true\` CAS, and existing \`match_result_reverted\` event is inserted.
11. If an internal controlled correction operation ID was supplied, update exactly one existing authorized receipt inside this transaction, checking expected revision/completion action/stage vector/expiry/actor. A failed receipt CAS aborts all TS-B writes, not just the receipt. Direct public Revert continues current authorization until separate MP2B policy.
12. **COMMIT only if every check and row count succeeds**. On any 409/4xx, deadlock retry exhausted, mid-step injected exception, absent/malformed legacy provenance or concurrent completion/Undo/routing, return safe typed error with **zero partial writes**, no stale champion or partial roster.

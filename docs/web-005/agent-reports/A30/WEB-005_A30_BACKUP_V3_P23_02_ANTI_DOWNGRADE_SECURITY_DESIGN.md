## 2. Threat model and severity

| ID | Classification | Confirmed precondition / security consequence | Evidence status |
|---|---|---|---|
| AD-01 / P0 | Marker stripping / strict→legacy downgrade | New strict provenance is unauthenticated without an external attestation; treating `!strictPolicy` as `legacy` would bypass B2/B3/B4/B5. A partially stripped modern file may pass a legacy-shaped schema. | **Real missing provenance and missing live gate SOURCE_CONFIRMED**; successful malicious import **NOT_DEMONSTRATED**; PR56 currently NOT_WIRED. |
| AD-02 / P0 | Parser-profile differential | Zod union may remove `strictPolicy`, and `schemaVersion:zod.number()` does not tag union branches. A validated raw marker could disappear/choose a differently shaped parsed payload. | **SOURCE_CONFIRMED schema omission**; specific wrong-union-path exploit **HYPOTHESIS_TO_TEST**. |
| AD-03 / P0 | Recognized nested foreign ID | The `?? value` remap fallback can retain foreign source integer in restored Undo JSON instead of rejecting/restricting it. Some numeric values can collide across tenants. | **SOURCE_CONFIRMED fallback**; actual cross-tenant write **NOT_OBSERVED**. |
| AD-04 / P1 | Forged action/history/CAS | Old source lacks portable match-state CAS plus total typed action provenance. Global ID membership does not enforce action-local/stage graph consistency; current exported timestamps alone are not deterministic total order. | **SOURCE_CONFIRMED missing modern extension**; actual exploitable Undo **UNVERIFIED**. |
| AD-05 / P1 | Historical-origin impersonation | A crafted file can mimic structural legacy shape. Structural allowlisting is **format compatibility**, not cryptographic proof of original creation date/issuer. | **INFORMATION-THEORETIC TRUST LIMIT**, no legacy signer in old formats. |
| AD-06 / P1 | Incomplete atomicity / privilege carryover | Pure module cannot prove preclone no-write or rollback; historical Undo payload may be treated as executable authority; clone requires new credentials, not source tokens. | **CURRENT ROUTE transaction/credential boundary SOURCE_CONFIRMED**; physical regression pending. |
| AD-07 / P1 | Resource exhaustion/parser confusion | Nested recursive Undo trees, massive arrays, deep objects, duplicate JSON members, unbounded sidecars and conflicting capability fields may create inconsistent classification or excessive CPU/memory. | **DEFENSE-IN-DEPTH DESIGN REQUIREMENT**, not observed incident. |

**Key security limitation:** A markerless malicious modern backup stripped down **byte-for-byte** to an allowed historical format is indistinguishable from an unsigned genuine old backup on content inspection alone. **No structural regex or missing-marker check can solve this.** To assert strict-origin anti-downgrade, require an **authenticated issuer receipt/signature or trusted immutable export registry**; otherwise classify compatible historical-looking input as **UNATTESTED_LEGACY_COMPAT**, never as proven authentic. Even if accepted, it must have strictly less authority (especially no historical destructive Undo/Revert/CAS replay). B1-A owner-approved legal legacy compatibility remains possible, **not** a free strict bypass.

## 3. Design alternatives (security/product trade-off)

| Variant | Architecture | Benefits | Limitations | Decision |
|---|---|---|---|---|
| A — marker-only | `if(strictPolicy) strict else legacy`, Zod parse first | Small patch | **Unsafe:** trivial stripping/unknown-key loss and modern/hybrid bypass | **REJECT** |
| B — raw classifier + positive historical structural allowlist | Raw inspect first; detect modern-only fields and hybrids; allow only verified legacy shapes with hard downgrade of unsafe operations | Minimal near-term compatibility with current unsigned old V2/V3 | **Cannot authenticate true legacy origin**; a perfectly forged old shape remains indistinguishable | Acceptable **only** as restricted compatibility lane, never as full anti-downgrade guarantee |
| C — authenticated strict export envelope + bounded legacy allowlist (**RECOMMENDED**) | Future strict exporter signs canonical payload and explicit profile/capabilities; raw classifier checks signature/provenance before typed Zod, passes immutable profile decision through all phases; legacy whitelist is positive, restricted and untrusted unless independently attested | Strong strict authenticity/tamper detection; portable proof; no marker-strip strict privileged import; legal old backups still recover safely | Key management, canonicalization, API/UI and limited legacy mode require A00/A20/A70/A90 coordination | **RECOMMENDED target architecture** |
| D — trusted server export ledger/known digest allowlist only | Verify exporter snapshot digest and issuance record outside file | Strong for files indexed by same trusted issuer | Breaks portability/offline/multiple issuers without shared trust/registry and excludes many genuine old files | Optional supplemental control, **not** sole universal compatibility strategy |

### Recommended C: trust and profile classifier (formal policy)

**Trust envelope (proposed, not present today):** outside or inside an explicitly versioned wrapper, retain a validated `profile=web005.backup-v3.strict.v1`, schema/producer version, capability set, portable action/state sidecar, issuer key ID and a signature/digest covering **all security-relevant payload bytes**, including profile, modern revision/action arrays and source IDs. Prefer modern signature such as **Ed25519** over a canonicalized JSON byte representation (defined serialization/canonicalization rules, e.g. deterministic JSON canonicalization), with trusted issuer public-key registry, rotation/revocation policy and optional issuance ledger. Signature key **is never exported**; signature does not transfer organizer/viewer/support privileges. Reject unknown issuers, bad signatures, duplicate/ambiguous encodings and unsupported profile versions.

**Mode selection MUST occur on the raw, bounded JSON document before any stripping Zod parse:**
1. `VERIFIED_STRICT`: explicit known strict envelope + valid authenticated origin + complete capabilities; run strict schema + \`validateBackupV3\` common invariants + PR41 flow checks + \`validateStrictBackupV3Policy\` + action-local/graph remap preflight; clone only after all pass.
2. `STRICT_MARKED_UNATTESTED`: marker present but issuer/signature missing. **Never demote to legacy**. Choose explicit 400 `INVALID_BACKUP_V3` (recommended default if signatures are required) or separately approved full strict *untrusted* validation with no extra privileges; owner must choose before code GO. Bad signature always invalid, not legacy.
3. `LEGACY_ATTESTED`: known old producer backup with genuinely verified issuer/archival provenance (e.g. trusted digest of an archived original) and exact historical schema shape; enter restricted legacy path, never silently upgrade to strict.
4. `LEGACY_COMPAT_UNATTESTED`: no strict marker/signature and **positive match** to a documented historical V2/V3 producer schema fingerprint/profile, no modern-only fields, contradiction or unsafe recognized ID; allow only **restricted data recovery** after ordinary auth/graph checks and explicit organizer-facing warning. Keep provenance state server-side and **disable historical destructive Undo/Global Undo/Direct Revert and replay of untrusted action/CAS tokens** until a new provably authorized local action establishes safe provenance. An unproven old result can be shown for historical reporting, not adopted as an authority token.
5. `AMBIGUOUS_OR_TAMPERED`: modern-only sidecars without marker, invalid signature, unsupported marker/version, wrong capability combinations, mismatched profile after parse, malformed or contradictory mixed format; fail **400 INVALID_BACKUP_V3 before any INSERT**, not fallback to legacy.

**Nonnegotiable:** confidence in legacy structure ≠ confidence in legacy origin; classification records must use distinct labels and auditable reasons. To **guarantee** that an adversary cannot intentionally rewrite modern data into a syntactically valid legacy file, the importer requires a trusted external provenance/issuer registry or else must reject unattested files. B1-A explicitly requires old legal support, so the recommended compromise is **restricted legacy import with zero privilege of historical Undo/CAS/action-token replay**. A00 must explicitly approve that security-mode implementation detail, issuer trust model and treatment of unsigned strict; this report does **not** silently override owner policy.

## 4. Minimal security contract for implementation before any importer wiring

**GATE-01 / raw ingress:** Normalize `req.body.backup` exactly once. Apply request size/nesting/entity limits. Classify raw provenance before Zod; preserve raw marker/envelope and compare with parsed result. Reject ambiguous duplicate JSON members or unsupported encodings rather than using first/last field inconsistently. Avoid logging raw credentials/backups or exposing sensitive nested objects in error details.

**GATE-02 / schema anti-confusion:** Update authoring OpenAPI `lib/api-spec/openapi.yaml` with explicit strict vs V2 vs legacy V3 formats; regenerate `lib/api-zod/src/generated/api.ts` and DTOs using the existing generation pipeline (**do not hand-patch generated code**). Use literal `schemaVersion=2/3` and **discriminated/tagged strict format** with `strictPolicy` parsed as required validated object, strict object behavior for modern unknown sensitive fields. Legacy allowlist uses precise historical shape and explicit unknown opaque data policy. Round-trip `raw→Zod→validator` MUST preserve classifier result and all mandatory modern sidecars; no fallback to wrong union branch.

**GATE-03 / provenance / legacy policy:** Maintain versioned positive historical producer-shape fixture manifest (from known commit/exporter, date range/issuer when evidenced, checksums, accepted optional/missing fields, e.g. `resultHistory:[]`, `actionLog:[]`, `undoPayload:null`, optional phases). Those checksums authenticate only archived verified files, not arbitrary new bytes sharing a shape. Bind classification `VERIFIED_STRICT` or `LEGACY_COMPAT_UNATTESTED` to restore transaction/capability record. Missing strict marker alone **never** means legacy.

**GATE-04 / domain validation:** Execute baseline common `validateBackupV3` (and appropriate PR41 QP/QPE/OP flow validation on an integration-approved source), strict sidecar validator for new profile, plus action/stage/participant consistency. Match `stateRevision` is distinct from result-history `revision`; modern completed match latest result/history/action must match. Legitimate completed `system_bye` needs a nonundoable `system_bye_assigned` (P23-01 fixed); manual completed matches need typed active action; walkover/NC handling as proven by A70. Total action order uses durable ordinal/tie-break, never timestamp alone.

**GATE-05 / nested reference closure:** Before mutation, build an **immutable typed source graph**: distinct valid exported player/stage/match IDs, stage memberships, match participants, action-local target and winner relations. For each recognized nested Undo ID, require source membership, appropriate relation to the **specific action** and stage, and eventual clone-local mapped target. Not sufficient to check \`Set.has(id)\` globally. Refuse `matchBackupId=21` action with nested `undoPayload.matchId=22` even when 22 exists. Validate `prevFeaturedMatchId` under tournament-wide semantics where legitimate, not incorrectly same-stage; opaque legacy keys must remain non-executable, not arbitrary numeric foreign references. Modern missing mapping = typed preclone **400**; never `map.get(id) ?? id`. For legacy unable to prove relation, sanitize/disable unsafe historical actions before inserting action log, with explicit warning.

**GATE-06 / transaction/auth:** Finish all pure preflight before `db.transaction` and before clone root INSERT. Inside **one DB transaction** generate clone-local player/stage/match/action/CAS references, insert all records and restore config/capabilities, enforce clone-only IDs and authenticated access; rollback entire clone on any late error. No reused original `hostCode`, organizer/support/viewer bearer/hash or source authorization session. Never create a source-tenant mutation side effect from imported Undo metadata. New clone organizerToken returned **only after commit**, for the new clone, private viewers require a new viewer password. Any restored legacy-inhibited Undo/Revert guard must be checked server-side, **not only hidden in UI**.

**GATE-07 / explicit errors/observability:** Invalid strict/hybrid/foreign ID => stable HTTP **400 `INVALID_BACKUP_V3`**, zero clone roots/children. Late induced PG failure => full rollback; safe error code, **no success token**, no stack trace or raw undo payload in response/log. Structured audit may record bounded profile outcome, reason code, content digest (not raw backup), new clone ID only after commit. Keep authorization errors distinct from schema errors.

**GATE-08 / independent acceptance:** A60 exact new combined HEAD + A50 isolated full-checkout Node22/pnpm10 typecheck/unit/API and A20-approved disposable PG16 transaction tests, positive/negative fixture corpus, full rollback snapshot and approval of residual historical capabilities. A90 alone cannot self-sign full implementation; PR56 22/22 isolated unit PASS != live integration PASS.

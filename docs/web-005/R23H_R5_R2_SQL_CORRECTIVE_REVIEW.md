Lost CREATE or COMMENT acknowledgement is treated as ambiguous/HOLD, not permission to destroy.

**New B01 details (P0 source blocker):** SQL lines 314–320 of `dropRunSchema` joins `pg_depend` to `pg_class` *as both dependent and referenced catalog class*. PostgreSQL 16 stores general dependencies with `classid/refclassid` indicating the catalog of each object. A view's SELECT dependency can be stored under `pg_rewrite`, and cascading through a view's internal rule may drop a view outside the run schema. Dependencies on types, functions, constraints and extension/member objects cannot be excluded by this narrow relation-only join. The query's `foreign_count=0` is therefore a false assurance of no foreign cascade: **the code may reach `DROP SCHEMA ... CASCADE` without comprehensive proof that its deletion closure is wholly run-owned**. PostgreSQL docs: https://www.postgresql.org/docs/16/catalog-pg-depend.html. **Required A50 action:** replace partial query with independently reviewed complete dependency resolution or a verified no-foreign-dependency invariant in an authenticated fresh, exclusive disposable S1 base; negative source/PG cases including a cross-schema view/trigger/function/domain/constraint and helper schema; fail closed if closure incomplete or unsupported.

**Additional scope limit:** `createdSchemaReceipts` is an in-memory Map with durable copy files; the journal file does not authenticate the server's original DDL event. Crash between SQL CREATE and receipt leaves an orphan needing independently signed G5, correctly nondestructive, but not yet proven operationally recoverable. `DROP SCHEMA ... CASCADE` is non-atomic with prior identity/dependency checks against third-party writers; race controls are external.

### SQL-trigger side effects / no runtime execution

1. `lib/db/migrations/0002_tournament_stages_v1.sql` Git blob `45fc166c312a97b68717dae4e3eb33b956da578f`: `tournaments_create_single_stage` inserts stage on new tournament; `tournaments_sync_single_stage` updates stage and increments version on selected tournament fields; `tournament_stages_sync_active_pointer` **updates parent tournament after stage status INSERT/UPDATE**; `players_sync_single_stage_participant` INSERT/UPSERTs memberships, resequences `players.seed` and `stage_participants.stage_seed`, and modifies stage participantCount; after player delete analogous count/resequence.
2. `lib/db/migrations/0026_basket_authority_trigger_bypass.sql` blob `92e0c8e8e37684f7c7b1b397e1839cb5f496c7ab` revises stage sync behavior for group/route modes. `0027_preserve_started_stage_memberships.sql` blob `90b9fd1c7297097d32ddbb546f9828c47fda02dc` revises the player-trigger behavior, preserving frozen started stages while still updating planned stage counts when eligible.
3. **Lock inversion hazard:** any code writer that locks stage BEFORE tournament may encounter trigger `tournament_stages_sync_active_pointer` writing parent afterward, racing with CAS parent-first. Correct **root cause at caller entry**, not by pretending a row lock on stage is sufficient. Existing bare compatibility player wrapper is one concrete unguarded path.
4. **Digest bypass hazard:** compatibility player triggers can update stage count/seed without incrementing `stage.version`. Canonical CAS roster digest must include actual player identity/seed/status, memberships and stage count/config; only version-based digests are insufficient. Direct DB writes, workers or restore must be barred from bypassing parent-lock protocol via DB privileges/trigger or explicitly handled fail-closed until verified. **No trigger DDL is authorized.**

## 2. Exact GET / ETag contract for A50's current protocol

PR146 `artifacts/api-server/src/domain/tournament/basket-cas-server-core.mjs` Git blob `ac5e5f4d94a540f843785822d1f08c3582ef32f7` implements a **pure/DB-free** adapter protocol, `basketCasEtag` with canonical bytes of domain `WEB005/BASKET-CAS/ETAG/V1`, tournamentId, epoch, revision, **caller-provided 64-character stageDigest and rosterDigest**. Test blob `71175659375c4bc71ef912d7b3405115ac4bd638` covers 14 mocks. **Neither digest's trusted DB source, canonical field selection, isolation nor immutable transaction is implemented.** A50 must not accept client-provided digests or return a token based on stale/off-tx data.

Minimum stageDigest canonical fields: sorted stage ID, stageKey, position, status, version, format, participantCount, planned/advancing counts, qualification mode, group/seeding/ranking policies, groupCount, qualifiersPerGroup, participantsPerGroup, stage lifecycle flags and authority mode; include any field used by `validateStageBasketConfiguration`, `validateTournamentStagePlan` or subsequent derived routing. Minimum rosterDigest: sorted player id, tournament id, seed/status and relevant properties; sorted stageParticipant (stageId/playerId/status/stageSeed/qualificationSource) membership and basket input assignment identities when not fenced solely by revision. Pin which attributes are truly relevant and exact canonical encoding; avoid ordering/NULL/date/time ambiguity. **Version alone cannot substitute field content.**

**GET**: from authenticated/authorized read, begin `READ ONLY REPEATABLE READ`, load epoch+revision, stages, players/memberships, graph and any routing authority in one snapshot, derive canonical digests and ETag from that snapshot, return body and strong ETag, with `Cache-Control: private, no-store`; a previous-snapshot GET is fine because PUT rechecks in its own serialized transaction. No root route modifications now.

**PUT**: in single transaction, acquire tournament parent `FOR UPDATE` first, revalidate organizer **under lock**, parse strict strong If-Match; read all version/digest inputs inside lock; calculate current ETag using **trusted** server data; reject malformed 400, missing 428, stale 412 **before any writes**; deny immutable stage; validate graph; check bigint overflow; perform existing graph delete/insert + derived stage/routing changes within that same transaction; perform one guarded `revision = revision+1 WHERE previous_revision=expected` returning exactly 1 row, even for valid no-op; read coherent resulting state; COMMIT then return body + new ETag. Every error rolls back graph, routing, stage version/count, revision and any action log. If caller-received tx was not locked or reauthorized, **FAIL CLOSED** rather than guess.

**RESTORE/CLONE**: new target creation only, from A90-authorized issuer/importer; database default generates NEW UUID epoch and revision zero; never copy these fields from uploaded JSON, source event history or existing tournament; for in-place restore return a refusal until separate policy GO. Internal clone transaction must include tournament+stages+players+baskets+routes+credentials and rollback atomically; 0 partial target on error. A signature alone does not grant historical Undo/Revert/CAS.

# V5.2: odtwarzanie kopii zapasowej V3 — stan i warunki włączenia

`BACKUP_V3_IMPORT` **pozostaje wyłączony**. V5.2 nie dodaje żadnej nowej ścieżki zapisu.

## Co działa w V5.2

| Element | Stan |
|---|---|
| Eksport V3 (organizator) | Działa: turnieje indywidualne, drużynowe (składy + historia), ligi z rewanżami, wieloetapowe. |
| Silnik odtwarzania (`importBackupV3`) | Sprawdzony testami na **osobnej bazie**, w osobnym procesie: turniej indywidualny z cofnięciem i korektą, drabinka drużynowa ze zmianą składu, liga drużynowa mecz-rewanż. Dane przed i po są identyczne (`team-backup-roundtrip.integration.test.ts`, 4/4). |
| Okno „Przywróć backup” | Dla pliku V3 pokazuje **podgląd tylko do odczytu** (nazwa, data, uczestnicy/drużyny, etapy, mecze, historia wyników, składy) i **kontrolę spójności** (brakujące sekcje, mecze wskazujące nieistniejących uczestników lub etapy, drużyny bez wpisu, składy w turnieju indywidualnym, pola z danymi logowania). Nic nie jest wysyłane na serwer, przycisk przywracania jest ukryty. |
| HTTP `POST /api/tournaments/import` dla V3 | Odrzuca z `BACKUP_V3_IMPORT_DISABLED` (bez zmian). |

## Czego brakuje do bezpiecznego włączenia przywracania przez organizatora

To wymaga osobnego zatwierdzenia bezpieczeństwa:

1. **Autoryzacja importu.** Dziś import tworzy nowy turniej bez logowania (jak dla V2). Dla V3 trzeba zdecydować, kto może odtwarzać, i dodać limit częstotliwości oraz rozmiaru.
2. **Pochodzenie pliku.** Kopia nie jest podpisana, więc serwer nie odróżni pliku z eksportu od spreparowanego. Strukturalna walidacja (`validateBackupV3`, ścisłe OpenAPI) jest kompletna, ale nie potwierdza autentyczności. Opcja: podpis HMAC przy eksporcie, weryfikowany przy imporcie.
3. **Test akceptacyjny na kopii produkcyjnej.** Należy odtworzyć zanonimizowaną kopię prawdziwej bazy na odizolowanym środowisku i porównać wyniki.
4. **Dziennik audytu.** Zapis „turniej odtworzony z kopii X” z sumą SHA-256 pliku.
5. **Decyzja produktowa.** Kopia odtwarza się jako **nowy** turniej z nowymi hasłami (tak jak V2), czyli dotychczasowe linki do widoku widzów się zmienią.

## Procedura awaryjna (administrator, bez włączania importu)

1. Organizator przekazuje plik `.json` z eksportu. W oknie „Przywróć backup” sam sprawdza, czy plik jest kompletny.
2. Administrator liczy sumę SHA-256 pliku i zapisuje ją w zgłoszeniu.
3. Odtworzenie odbywa się **wyłącznie na odizolowanej bazie testowej lub stagingowej** tym samym kodem co test (`artifacts/api-server/test/support/backup-restore-child.ts`). Skrypt sam odmawia celu, który nie jest lokalny albo nie ma „test” w nazwie bazy.
4. Po weryfikacji wyniku decyzję o przeniesieniu danych na produkcję podejmuje właściciel. Skrypt nie przenosi niczego automatycznie.

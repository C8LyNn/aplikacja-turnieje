# V5.9 — tryb transmisji (nakładki OBS) i domknięcie V5.8

Punkt wyjścia: V5.8 `43b00e5` (migracje do 0046). **V5.9 nie zmienia API ani bazy i nie ma migracji.** Nakładki
czytają te same publiczne odpowiedzi API co widok widza; jedyna operacja zapisu w nowym panelu to istniejące
„Na ekranie” (`featuredMatchId`, ta sama operacja co gwiazdka w panelu prowadzącego).

## 1. Domknięcie problemów V5.8 (etap A)
* **Stable — podwójna eliminacja w zakładce „Drabinka”.** Przyczyna: `StageProgressView` (zakładka „Drabinka”)
  obsługiwał grupy, pojedynczą eliminację, szwajcarski i ligę, a dla `double_elimination` zwracał `null`.
  Drabinka DE była tylko w zakładce Etapy. Teraz zakładka czyta ten sam stan podwójnej eliminacji co Etapy
  (tylko do odczytu, z ponowieniem przy błędzie). Dotyczy Stable i Experimental; wygląd Stable bez zmian.
* **Koszyki — zbiorowa obsługa** (tryb „Zaawansowane koszyki”, sekcja „Uczestnicy w koszykach startowych”):
  filtr „Wszyscy / Start A… / Bez koszyka”, wyszukiwanie (bez polskich znaków), zaznaczanie wielu (klawiatura,
  dotyk, „Zaznacz widocznych”), „Przenieś zaznaczonych do” koszyka, do **nowego** koszyka startowego albo
  „Usuń z koszyka”. Przed zmianą: **podgląd** (kto skąd dokąd, liczby w koszykach przed → po) i to, co
  zablokuje start (liczba zaplanowana w etapie, układ grup) lub kogo pominie. „Zastosuj w szkicu” zmienia tylko
  szkic, „Cofnij ostatnią zmianę” cofa krok, „Zapisz konfigurację” zapisuje jak dotąd (API sprawdza wszystko
  ponownie). Bez przeciągania.
* **Koszyki, grupy, awans — rozróżnienie zachowane:** koszyk startowy ustala kolejność rozstawienia (Start A
  pierwszy), **grupy tworzy silnik przy starcie etapu** (wąż / losowo) — ręcznego przypisania do grup nie ma
  w modelu danych i V5.9 go nie dodaje; koszyki „Awans” i połączenia nie są ruszane.
* **Drobne (A3):** po odrzuconym zapisie pola „Przechodzi”, które wskazało API, są oznaczone (w przeglądarce
  wyszło, że domyślnego planu nie da się zapisać, dopóki ich nie uzupełnisz — API celowo nie zgaduje tych liczb).

## 2. Tryb transmisji
### Jak to działa
1. Turniej → **Więcej → Transmisja** (Experimental; sekcja opcjonalna, kreator i prowadzenie bez zmian).
2. Wybierz nakładkę: **Wynik meczu**, **Drabinka i tabele**, **Zapowiedź meczu**.
3. Wskaż mecz („Na ekranie” albo zawsze ten sam) lub etap i zakres (jedna runda drabinki, jedna grupa).
4. Wybierz zestaw wyglądu i ewentualnie szczegóły; podgląd pokazuje prawdziwą nakładkę na danych turnieju.
5. **Kopiuj adres** → w OBS źródło **Przeglądarka** → wklej.

Nakładka to osobna, lekka strona `overlay.html` (własny pakiet ~18 kB JS + wspólny React ~186 kB + 16 kB CSS);
OBS nie ładuje panelu organizatora (1,17 MB JS + 535 kB CSS).

### Adres nakładki
`<adres aplikacji>/overlay.html?t=<id turnieju>&…` — zapisywane są tylko wartości inne niż domyślne.

| Parametr | Wartości (domyślna pierwsza) | Znaczenie |
|---|---|---|
| `t` | id turnieju | wymagany |
| `widok` | `wynik`, `struktura`, `zapowiedz` | rodzaj nakładki |
| `mecz` | (brak) = „Na ekranie”, liczba = stały mecz | który mecz (wynik, zapowiedź) |
| `etap` | (brak) = bieżący, id etapu | struktura |
| `runda` | (brak) = cała drabinka, numer rundy | struktura, eliminacje |
| `grupa` | (brak) = wszystkie, np. `Grupa A` | struktura, grupy |
| `styl` | `arena`, `broadcast`, `minimal`, `sport`, `futuristic` | zestaw wyglądu |
| `uklad` | `pelny`, `kompakt` | wariant paska wyniku |
| `rozmiar` | `m`, `s`, `l` | rozmiar wyniku |
| `tytul` | (brak) = pokaż, `0` = ukryj | tytuł turnieju |
| `tlo` | `przezroczyste`, `pelne` | tło na obraz gry / osobna scena |
| `ruch` | `1`, `0`, `2` | animacje: łagodne / brak / wyraźne (szanuje „ogranicz ruch”) |
| `tekst` | `1`, `1.25`, `1.5` | wielkość tekstu |
| `pozycja` | `dol`, `gora` | położenie paska wyniku |
| `kolejka` | (brak), `1` | zapowiedź: 3 kolejne mecze etapu |

Nieznane lub zepsute wartości wracają do domyślnych; adres nie przyjmuje żadnych danych logowania.

### Odświeżanie i brak połączenia
* Wynik i zapowiedź: odczyt co **5 s** (turniej + mecze, jedno i drugie publiczne); etapy co 60 s.
  Struktura: co **10 s**. Identyczna odpowiedź nie przerysowuje nakładki (brak migania i powtórzonych animacji).
* Pokazywane są wyłącznie **zapisane** wyniki — wynik wpisany w edytorze, ale niezapisany, nie trafia na nakładkę
  (sprawdzone w przeglądarce: 8 s po kliknięciu „+” nakładka nadal pokazywała „– : –”).
* Brak połączenia: zostaje ostatni zapisany stan z dyskretnym znacznikiem „Brak połączenia — ostatni zapisany
  stan”; kolejne próby coraz rzadziej (do 30 s); po powrocie API znacznik znika sam.
* Turniej prywatny / nieistniejący: komunikat zamiast danych, ponowna próba co 30 s (zmiana widoczności zadziała
  bez zmiany adresu). Ukryta karta przeglądarki odpytuje co 30 s.
* Bez WebSocketów — odpytywanie wystarcza dla tego zastosowania.

### Bezpieczeństwo
* Każde zapytanie nakładki jest **anonimowe** (`credentials: "omit"`, bez nagłówka tokenu) — także gdy
  nakładkę otworzy przeglądarka zalogowanego organizatora. Nakładka widzi dokładnie to, co widz turnieju
  publicznego; turniej prywatny daje komunikat „Nakładki działają tylko dla turniejów publicznych”.
* Dane przechodzą przez jawną listę pól (nazwy, wyniki, sety, stan, runda, termin, wiersze tabel). Notatki,
  powody wyników, pola uczestników i informacje o dostępie nie są czytane ani pokazywane.
* Nakładka jest tylko do odczytu: brak przycisków, logowania i operacji. Token organizatora nigdy nie trafia do
  adresu.

## 4. OBS — instrukcja
1. **Źródła → + → Przeglądarka** (Browser).
2. **URL**: wklej adres z „Kopiuj adres”.
3. **Szerokość / wysokość**: jak rozdzielczość sceny — 1920 × 1080 albo 2560 × 1440 (panel podaje liczby dla
   wybranej rozdzielczości).
4. Pole „Własny CSS” zostaw puste. Przezroczyste tło działa od razu; „Pełne” to osobna scena (np. przerwa).
5. **Wybór meczu**: gwiazdka „Na ekranie” w panelu prowadzącego albo „Pokaż na ekranie” w sekcji Transmisja —
   adres w OBS się nie zmienia. Można też przypiąć jeden mecz („Zawsze ten sam mecz”).
6. **Sprawdzenie odświeżania**: zapisz wynik w panelu prowadzącego; nakładka pokaże go po kilku sekundach.
   Podgląd w sekcji Transmisja to ta sama strona.

Nie zweryfikowano w samym OBS (brak OBS w środowisku testowym) — renderowanie, przezroczystość (zrzuty z kanałem
alfa), odświeżanie i brak połączenia sprawdzono w przeglądarce Edge (Chromium, jak silnik źródła OBS).

## 5. Ograniczenia
* Brak logotypów i avatarów — aplikacja nie przechowuje takich danych; nakładki niczego nie dorabiają.
* Logo wydarzenia w zapowiedzi — brak (jw.).
* Nakładki tylko dla turniejów publicznych; dla prywatnych pokazują komunikat (nie ma bezpiecznego mechanizmu
  dostępu bez tokenu w adresie).
* Odświeżanie przez odpytywanie (5 s / 10 s), nie natychmiast.
* Sekcja „Transmisja” jest w Experimental; Stable pozostaje interfejsem awaryjnym bez niej (adresy nakładek
  działają niezależnie od interfejsu).
* Ustawienia nakładki żyją w adresie — nie są zapisywane w turnieju.
* Koszyki: ręcznego przypisania do grup nie ma (grupy tworzy silnik); zbiorowe przenoszenie dotyczy koszyków
  startowych.
* Pole `note` meczu jest w publicznej odpowiedzi API od wersji sprzed V5.9; interfejs go nie pokazuje, nakładki go
  nie czytają.
* Testy intuicyjności wykonał agent w przeglądarce, nie ludzie.
